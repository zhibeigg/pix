# 管理后台创建账户 — 设计文档

- 日期：2026-07-22
- 状态：已确认并进入实现
- 版本号：`1.135.12 → 1.136.12`（B 位：新增功能）

## 1. 背景与目标

Pix 已有公开邮箱验证码注册和管理员用户列表，但后台不能直接创建账户。运维需要临时账户时只能进入生产容器执行脚本，容易遗漏密码策略、点数账户或注册赠送初始化。

目标是在「后台 → 用户与点数」中提供受管理员权限保护的创建入口，并让前端、管理员 API 与公开注册复用同一组安全和初始化规则。

## 2. 已确认决策

| 决策点 | 结论 |
|---|---|
| 权限 | 仅 `require_admin` 通过的管理员会话或管理员 Bearer Token 可调用。 |
| 新账户权限 | 固定 `role=user`、`status=active`；请求不能传入角色、状态或点数。 |
| 邮箱验证 | 管理员创建跳过验证码并立即激活，但仍校验邮箱格式、规范化大小写并保证唯一。 |
| 密码 | 9～128 字符，必须同时包含英文字母和数字；仅保存 Argon2 哈希。 |
| 昵称 | 可选；空值时使用邮箱本地部分。 |
| 初始点数 | 建立 `CreditAccount`，并读取当前 `registration_bonus_credits` 发放与公开注册相同的赠送点数。 |
| 数据库 | 不增加字段，不需要 Alembic 迁移。 |

## 3. API 契约

### `POST /admin/users`

请求：

```json
{
  "email": "new-user@example.com",
  "password": "Temporary123",
  "display_name": "New User"
}
```

成功响应：`201 Created`，返回 `AdminUserResponse`，包含用户基础信息、初始点数与会员字段，不包含密码或密码哈希。

错误：

- `401`：未认证。
- `403`：当前用户不是管理员。
- `409`：邮箱已注册；包括预检查命中和并发唯一约束冲突。
- `422`：邮箱、密码、昵称不合法，或请求包含 `role`、`status`、点数等额外字段。

管理员 API 不接受外部 API Key，外部自动化账户不能获得后台用户管理权限。

## 4. 事务与并发

创建用户、建立点数账户和发放注册赠送在同一数据库事务中完成。提交失败时统一回滚，避免留下只有用户、没有点数账户的半成品。

接口先查询邮箱以提供清晰错误，再捕获数据库 `IntegrityError` 处理并发重复创建；两条路径都返回 `409`，不暴露底层数据库异常。

## 5. 前端交互

创建表单位于现有用户列表和批量点数操作之前，字段为邮箱、昵称和临时密码。

- 明确提示账户会立即激活、无需邮箱验证码、只能创建普通用户。
- 展示密码长度与组成规则。
- 提交期间锁定按钮，失败时在表单内显示后端错误。
- 成功后清空敏感输入、刷新用户资源并显示成功通知。
- 继续复用现有紧凑后台布局，在窄屏下字段纵向排列。
- 所有新增文案同时提供简体中文和英文翻译。

## 6. 配置行为

不新增环境变量。管理员创建账户复用数据库系统设置 `registration_bonus_credits`；默认值保持不变。默认配置说明和 `config.example.toml` 注释会明确该设置同时作用于公开注册与管理员创建。

## 7. 安全边界

- 后端固定角色和状态，不信任前端隐藏字段。
- Pydantic 模型设置 `extra="forbid"`，拒绝越权字段。
- 密码不写日志、不进入响应，也不保存在前端成功状态中。
- 使用现有 Argon2 `hash_password`，不新增弱哈希或可逆加密。
- 创建接口不发送包含密码的欢迎邮件，避免凭据二次传播。

## 8. 验证范围

后端覆盖成功创建、密码哈希、邮箱规范化、默认昵称、赠送点数、重复邮箱、请求校验和权限拒绝。前端覆盖 API 序列化、Cookie 会话行为及中英文表单静态渲染。最后执行完整 pytest、Ruff、Vitest、TypeScript/Vite 构建和版本一致性检查。
