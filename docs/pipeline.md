# Pix 素材生成流水线

本文档描述当前网站后端的主要图像处理顺序。实现以 `src/pix/` 与 `src/pix_web/` 为准。

## 通用后处理顺序

对 AI 生成图或上传图进行像素化时，默认顺序为：

1. Perfect Pixel 网格检测与对齐；
2. 去背景（唯一一次早期抠图，包含封闭区域）；
3. 按 alpha 包围盒裁剪主体；
4. 下采样到目标像素网格；
5. 按配置限制颜色或应用调色板；
6. 仅在用户选择时应用描边或羽化；
7. 将主体按比例放入最终画布，使用透明像素补齐，不裁切主体；
8. 输出 PNG、网格元数据和任务产物索引。

早期去背景得到的 alpha 会参与主体定位和裁剪。描边/羽化在量化后执行，下采样阶段会为边缘效果预留透明空间。

## 单图素材

### 无参考图

用户参数 → 构建服务端 prompt → 生图 → Perfect Pixel → 去背景 → 裁剪主体 → 下采样 → 调色板/限色 → 可选边缘处理 → 最终透明画布 → 返回产物。

### 有参考图

用户参数与参考图 → 构建带“参考图/图1”语义的 prompt → 图生图 → 与无参考图相同的本地后处理。参考图只是生成输入，不绕过后端尺寸、背景、像素网格和安全约束。

## Mosaic 序列帧

序列帧模式一次生成完整 sheet。后端根据请求的行列数和单帧尺寸选择合法的上游渲染分辨率，然后：

1. 沿整轴逐像素扫描背景、主体和 gutter，先按动作行切分，再按帧切分；
2. 对每帧执行 Perfect Pixel 和显式 key-color 去背景；
3. 按 alpha 裁剪主体并清理孤立噪点；
4. 根据显式配置保留原色、应用共享 ramp，或使用本地 K-means；
5. 应用可选描边/羽化；
6. 跨帧统一到自适应画布，保持底部锚定与相对位置；
7. 输出横向 sheet、二维网格预览、单行动画、帧目录和 `sequence.json`。

交付帧可能因主体高度和安全边扩展为非请求高度，元数据会通过 `delivered_frame_size` 与 `frame_size_adapted` 标明实际尺寸。

## 首尾帧视频补间

`video_bridge` 模式先生成首帧或首尾关键帧，再调用配置的视频上游生成短视频。任务在远端生成期间保持 `waiting`，到达 `next_poll_at` 后继续轮询，不长期占用 worker。视频完成后均匀抽取目标帧数，并对所有帧使用统一的 Perfect Pixel 网格、去键色污染、透明安全边和画布规则。

## 本地像素化

本地像素化不调用生图服务。输出尺寸优先采用 Perfect Pixel 检测到的真实像素网格，再执行去背景、裁剪、调色板/限色、可选边缘处理和透明画布定版。

## 安全边界

- Prompt guard 审核用户原始输入，不向外部审核服务暴露服务端完整模板。
- 所有用户文件路径必须经过归属校验，不能直接信任请求中的路径。
- 外部下载必须经过 SSRF 防护并逐跳校验重定向。
- API Key、JWT Secret、数据库凭据只允许来自环境变量或受控配置存储，不得写入产物、日志或仓库。
