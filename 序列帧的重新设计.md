# 序列帧设计

## 示例prompt

A detailed top-down pixel art sprite sheet for an adventurous soldier character, directly based on the design seen in image_0.png. This new sheet should be an exact 8x8 grid of sprites, maintaining the overall arrangement and art style of image_0.png, but completely re-designed with new content as a comprehensive character-specific action set. The core character design (green armored helmet with faceplate, orange/red tactical jacket, green trousers) remains consistent, but the actions are new.

Layout by Row (each row is an 8-frame animation loop):Row 1 (Walking North/North-East): 8 frames of the character walking diagonally upwards to the right.Row 2 (Walking East/South-East): 8 frames of the character walking diagonally downwards to the right.Row 3 (Attacking - Sword Swing - North): 8 frames of a north-facing sword swing, showing the arm pulling back and a full slash.Row 4 (Attacking - Bow Shot - East): 8 frames of the character pulling back and releasing a bowstring, with an arrow visible, facing right.Row 5 (Defending/Block - All Angles): 8 frames of a circular shield-blocking stance, transitioning through N, NE, E, SE, S directions.Row 6 (Interacting/Use - South): 8 frames of a south-facing character reaching and using an object (e.g., pulling a lever).Row 7 (Hurt/Knockback - North): 8 frames of a north-facing character reeling backward from an impact.Row 8 (Dying - Specific Sequence): 8 frames showing the dying sequence of image_0.png, re-ordered: (from L-R) Frame 1: Stumble (image_0.png frame 6), Frame 2: Collapse (image_0.png frame 1), Frame 3: CRAWL (image_0.png frame 2), Frame 4: ROLLING (image_0.png frame 3), Frame 5: FALL DOWN (image_0.png frame 4), Frame 6: DEAD-STILL (image_0.png frame 5), Frame 7: a brief twitch of the dead form, Frame 8: an empty corpse on the ground.

The new sprites must match the pixel scale and detail level of image_0.png. The pose and detail fidelity of each new action (e.g., the bow shot) must be high, clearly showing the weapon and the pose, at the same scale. The background remains pure black. All poses are crisp and distinct, preserving the vintage pixel art aesthetic.

## 解释

我想将序列帧功能改回单图生成，能不能根据这个prompt举一反三的进行设计，优化序列帧设计更契合我的网站。

# 实施方案（v1）

## 总体策略

**单图为默认 + 逐帧保留**：在 `sprite_sheet` 任务下新增「单图模式（mosaic）」作为默认生成方式，老的「逐帧模式（iterative）」保留入口。前端新增「生成方式」开关，后端走两条独立 pipeline，按生成方式分别计费。

## 概念模型

| 概念 | 说明 |
|------|------|
| **rows × cols** | 用户显式指定网格。rows=1 退化为横向条；rows=cols=8 为示例 prompt 的角色全动作集 |
| **frame_size** | 单帧逻辑像素尺寸（如 64×64）。整图实际像素 = `cols·frame_size × rows·frame_size`，由后端计算并传给生图 API |
| **行级动作描述（row prompts）** | rows 个独立文本框，描述该行的动作循环。rows=1 时只显示一个文本框 |
| **总体描述（subject brief）** | 描述角色/主体本身：服装、配色、风格 |
| **参考图（可选）** | 上传一张角色立绘。提供时调 `edit_image`；不提供时调 `generate_image` |

## 架构设计

### 后端

**新增模块** `src/pix/sprite_mosaic.py`：单图序列帧 pipeline。复用：
- `contact_sheet.split_contact_sheet`（切图）→ 改造成可指定 rows/cols 的版本
- `contact_sheet.resolve_key_color`（key 色选择）
- `sprite._finalize_frames` / `compose_horizontal_sprite_sheet`（后处理）
- `sprite._write_sequence_json` / 元数据格式（保持前端兼容）

**新接口**：

```python
# src/pix/sprite_mosaic.py
@dataclass
class SpriteMosaicInput:
    prompt: str                        # 主体描述
    row_prompts: list[str]             # 每行的动作描述；len == rows
    rows: int                          # 1..8
    cols: int                          # 1..8
    frame_size: tuple[int, int]        # 单帧逻辑像素，默认 64×64
    reference_image_path: Path | None  # 参考图（可选）
    image_size: str | None
    image_quality: str | None
    image_model: str | None
    pixelize_params: PixelizeParams
    out_root: str | Path | None
    use_cache: bool
    refresh_cache: bool
    fps: int
    gif_export: bool
    billing: dict[str, Any] | None
    local_stage_context: LocalStageContext | None

def run_sprite_mosaic_pipeline(cfg, inputs, progress=None) -> SpritePipelineResult: ...
```

**Pipeline 步骤**（单次 API）：

1. `validate_user_prompt`：审核「主体描述 + 拼接所有行描述」的合并文本
2. `build_mosaic_prompt`：用模板生成完整 prompt（包含 rows×cols 网格契约 + Layout by Row 段落）
3. 调用生图：
   - 有参考图 → `edit_image(reference, prompt, ...)`
   - 无参考图 → `generate_image(prompt, ...)`
   - 整图尺寸映射到 image_gen 支持的最近档位（1024/1536/2048）
4. `split_mosaic_sheet`：等分为 rows×cols 个候选单元
5. 对每个单元复用 `_extract_frame_content`（perfect-pixel + 抠色 + bbox）
6. `_finalize_frames`：共享调色板、贴齐画布
7. 输出：保留原 sprite_sheet.png（横向单行重排）+ 多行预览图 `sprite_mosaic.png`（保留生图原版式）+ sequence.json

**sequence.json 兼容性**：现有前端 `SpriteSequencePreview` 按 `sheet_rect` 在横向 sheet 上抽帧播放。单图模式仍然按「row=0, col=index-1」横向布局输出 final sheet（保证旧前端继续播放），同时新增字段：

```json
{
  "type": "sequence_frames",
  "mode": "mosaic",
  "grid": { "rows": 4, "cols": 8 },
  "row_actions": ["Walking N", "Walking E", "Attack", "Death"],
  "mosaic_sheet": "sprite_mosaic.png",  // 原版 rows×cols 布局
  "playback_source": "sprite_sheet.png", // 横向重排，供旧前端逐帧播放
  ...
}
```

**Prompt 模板**（写到 SpriteConfig，可在管理后台改）：

```
mosaic_prompt_template = """
Create a TRUE pixel-art sprite sheet for the following subject.
Subject: {description}.
Layout: an exact {rows}x{cols} grid of sprites, read left-to-right then top-to-bottom.
Total canvas: {sheet_width}x{sheet_height} pixels. Each cell is exactly {frame_width}x{frame_height} pixels and aligned to the grid.
Each row is one independent animation loop with {cols} frames, listed below:
{row_block}
Character/subject consistency: keep the same identity, palette, outline thickness, scale, and proportions across every cell.
Background: use pure solid key-color {green} for ALL empty/background pixels for chroma-key removal; keep visible colors outside the maximum key-color tolerance ({key_tolerance} RGB Euclidean distance) from {green}.
Use no more than {max_colors} visible subject colors; background color does not count.
Style: crisp pixel art, hard edges, limited palette, no painterly blending, no anti-aliased soft brush. Every pixel must be a perfect square aligned to the grid.
Do not add text, watermark, UI, border, grid lines, labels, numbers, or shadows outside the subject. Do not draw extra frames outside the {rows}x{cols} grid.
"""

mosaic_reference_prompt_template = """
Re-create the sprite sheet below based on the provided reference image as the character source.
The reference image defines the core character design (silhouette, palette, costume, proportions).
{base_template}
Reuse the reference character identity in EVERY cell; only the action/pose changes.
"""
```

`{row_block}` 自动展开为：
```
Row 1: <row_prompts[0]>
Row 2: <row_prompts[1]>
...
```

**计费**：
- 单图模式：1 张图 = `5 × max(1, ceil((rows*cols)/9))` 点
  - 9 帧以内 5 点（与单帧任务齐平），更大网格按 9 帧档阶梯涨
  - 用 ceil 是因为大网格更耗 token，但远便宜于逐帧
- 逐帧模式：保留现状 `5 × frame_count`

### 前端

**新增字段**（`apps/web/src/types.ts` 的 `SpriteParams`）：

```typescript
export type SpriteGenerationMode = 'mosaic' | 'iterative'

export type SpriteParams = {
  // 旧字段保留
  frame_count: number
  fps: number
  ...
  // 新字段
  generation_mode: SpriteGenerationMode  // 默认 'mosaic'
  rows: number                            // 1..8
  cols: number                            // 1..8
  row_prompts: string[]                   // length == rows
  reference_image_path: string | null     // 可选参考图（使用现有 uploads 接口）
}
```

**面板改造**（`SingleGeneratePanel.tsx` 序列帧分支）：

```
[模式: 序列帧]
├── [生成方式]  ○ 单图（推荐，快·便宜）  ○ 逐帧（高保真闭环）
├── [主体描述] textarea（角色/服装/风格）
├── [参考图（可选）] 上传按钮 + 预览
│   └── 提示：提供后将以图生图模式保留角色设计
├── [布局]
│   ├── 预设：[1×N 横排] [4×8 四方向] [8×8 角色全动作集] [自定义]
│   ├── 行 rows: [4]   列 cols: [8]   单帧像素: [64×64]
│   └── 总帧数 = rows × cols = 32
├── [行动作]（仅当 rows ≥ 2）
│   ├── Row 1: textarea
│   ├── Row 2: textarea
│   └── ... rows 个
├── [播放 FPS]
└── [生成]
```

rows=1 时：行动作折叠为单一动作 textarea（与旧 prompt 等价）。

**预览**：`SpriteSequencePreview` 不动；新增的 `sprite_mosaic.png` 在画廊详情里作为「sheet 原版」可下载，逐帧播放仍读 `sprite_sheet.png + sequence.json`。

### 数据库 / Schema

`SpriteParamsSchema`（schemas.py）新增字段：

```python
class SpriteParamsSchema(BaseModel):
    # 既有字段保留
    ...
    generation_mode: Literal["mosaic", "iterative"] = "mosaic"
    rows: int = Field(default=1, ge=1, le=8)
    cols: int = Field(default=9, ge=1, le=8)  # 注意 le 调整
    row_prompts: list[str] = Field(default_factory=list, max_length=8)
    reference_image_path: str | None = None
```

兼容性：旧任务 generation_mode 缺省 → 视为 `iterative` 维持旧行为（以 frame_count 为准）。

### Pipeline 路由

`pipeline_adapter.run_pipeline_for_job` 增加分支：

```python
if job.job_type == "sprite_sheet":
    sprite_data = data.get("sprite") or {}
    mode = sprite_data.get("generation_mode", "mosaic")
    if mode == "mosaic":
        return run_sprite_mosaic_pipeline(cfg, mosaic_input_from_job(job, settings))
    return run_sprite_pipeline(cfg, sprite_input_from_job(job, settings))
```
